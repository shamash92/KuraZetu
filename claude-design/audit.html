Audit · Redesign brief · Punch list

Kura Zetu, candidly.
What's working, what's not, and what to ship first.

Companion doc to redesign.html. Skip the praise. The product is doing the right thing — the design just hasn't caught up. Below is the audit, prioritized, with what to ship in week 1 vs month 1 vs later.

Author · Designer · For the team · May 2026

01Trust posture

This is the hill the product lives or dies on. Citizens need to read the screen and know — in two seconds — that this is parallel data, not the IEBC. The current build is mostly there, but five things actively work against that read.

01

The word Dummy is in production copy.

"Presidential (Dummy) Results" is on the live dashboard. On election night, a journalist screenshots this. We do not recover. Remove this string before anything else on this list.

02

Debug variables are leaking to users.

registrationErrorLogin:"", Must use physical device for push notifications is showing up as a modal on the login screen. That string belongs in a developer console, not in front of a stressed rural user at 9pm.

03

The disclaimer is buried inside a phone mockup on the marketing site.

The "Important Disclaimer — This is not an official IEBC tallying system" chip is the most important piece of copy on the entire page, and it's stamped onto a stock phone illustration. It should be a persistent, screenshot-resilient band at the top of every results view, mobile and web (see redesign.html → System → Disclaimer).

04

Red + yellow is the wrong palette for a non-partisan civic tool in Kenya.

The current mobile primary (red Sign-In button) and the wordmark's yellow underline read close to Jubilee + UDA. This is not what you want anyone to feel when they open the app. The Ramani palette in the canvas — forest + sand + terracotta + eucalyptus + savanna gold — avoids every Kenyan party flag while still feeling rooted to place.

05

"Things are boiling nicely…" is the wrong tone for civic infrastructure.

It's a charming stock Lottie that reads as a banking app. On election night a user does not want to be told things are boiling. They want a textual progress indicator with a number ("loading 23,142 polling stations…") and an estimate.

02Consistency between web and mobile

The web and mobile apps were clearly built by different hands at different times. They share the wordmark and not much else.

01

Two different visual languages.

Web uses Bootstrap-y blue + green pill buttons; mobile uses near-Material red + maroon. There is no shared token system, so a single brand change requires two diffs. Ramani's tokens.css + a mirrored RN JSON fixes this — same hex values, same names, two files.

02

Different icon sets across surfaces.

Mobile already uses Lucide (per the package.json). Web uses Font Awesome 5 and inline SVG. Pick one — Lucide on both. Lucide is free, tree-shakable, and the icon vocabulary already matches the mobile build.

03

Auth experience diverges.

Web asks for phone + password on a split-screen; mobile asks for phone + password + biometric. Worse — web is heavier (Bootstrap, big assets, slower on 3G). Both should be phone-only OTP, no password. Most Kenyans don't have or remember a password for civic-tech apps; OTP every time, biometric local-unlock for repeat users on mobile only.

04

Web "Project Timeline" Kanban does not belong on a public landing page.

The launch board (Initial Requirements · Bootstrap Web Platform · PinVerify254 Game · Launch Mobile App) belongs in docs/ or a contributor portal, not on the homepage. It reads as "this is in beta, do not trust it."

03Accessibility

WCAG 2.2 AA is the floor. The stress / sun / cheap-Android / multi-lingual context demands AAA where feasible. The current build fails AA in several places.

01

Color-only signaling on the bar chart.

The dashboard "Governor Results" chart uses teal, terracotta, orange, navy, mint — five hues without labels at value-point. Colorblind users get nothing. Add the candidate name at the bar end + use shape-based icons for the four verification states (✓ ? ! —), not just hue.

02

Tap targets below 48dp on the pin-edit map.

The Leaflet pin handles and +/− zoom buttons measure ~28×28 in the current build. On Android at 320dp width, that's about a thumb-tip's worth of forgiveness. Bump to 44×44 minimum.

03

Polling-station codes shown as the primary identifier.

"031164082006901" is the IEBC identifier. It's not what a user calls their station. Lead with the name (Likii Primary School), demote the code to a mono caption, and let users search by name, church, or landmark. (See redesign.html → PinVerify A · Find station.)

04

No language switcher.

English-only on a country where Kiswahili is co-official and Sheng is the lingua franca of the urban under-35s. The onboarding flow in the canvas surfaces language as zero-step before any other choice. All copy needs to externalise to a JSON file; Kiswahili runs ~15-30% longer than English so re-test every screen at +30% width.

05

Reduced-motion not respected.

The "Things are boiling nicely" Lottie loops indefinitely; the map-load animation pulses. prefers-reduced-motion should kill both. Same applies to RN — check the user's AccessibilityInfo.isReduceMotionEnabled.

04Density & cognitive load

The IA correctly mirrors Kenya's electoral geography (county → constituency → ward → station). That's right. But every step is a full screen, every screen is a long list, and the user has to read the page from scratch each time.

01

Five taps to drill from National to Station.

Each tap is also a full-screen route change with a map reload. Replace with a persistent map + sliding bottom-sheet (Ramani country → drill in place) so the user keeps geographic context between steps.

02

"No Form 34A image available" empty state is the same shape as a result.

The user has to scroll to the bottom of an apparently-empty page to find the floating + button. Move the empty state to centre with a clear CTA ("Be the first to submit this station's Form 34A").

03

Long single-column candidate lists.

Ten candidates at 100% width, each on its own row, on a 360dp screen = vertical scroll. Group: top 3 prominent, rest collapsed under "+ 7 others." (See redesign.html → Results · Mobile.)

04

Confusing dual-presence pins on PinVerify edit.

The blue/red two-pin "139.5m" view is information-rich but unscannable. Replace with a before/after toggle + a single live pin + accuracy circle. (See redesign.html → PinVerify A · Walk to entrance.)

05AI / template tropes to retire

These all read as "I asked an LLM to give me an app." The product is real; the chrome around it shouldn't betray that.

01

Purple-blue gradient + trophy emoji on PinVerify.

Reads as Duolingo, not civic infrastructure. Keep the points (they work) — replace the background.

02

Left-bar accent on every callout.

"3px solid colored left border + soft tinted background" is the universal LLM banner. None in the redesign — color the icon, tone the bg, that's it.

03

Pill badges with a dot.

"● COMMUNITY-VERIFIED" inside a rounded fill is the same trope. The redesign uses mono small-caps in the state colour, no fill, no dot. Reads as a typographic tag, not a button.

04

Stock Lottie animations.

"Things are boiling nicely" + the dot-map "Loading Map Data" feel borrowed. A textual progress indicator with a real number is faster, cheaper, and more honest.

05

Hand-pointing-at-tablet wordmark icon.

The "FORM 3X" cartoon mark is clip-art. The redesign uses a 16×16 geometric ballot+check glyph with a single dot for the brand accent — civic, geometric, original, and printable at 12px.

06Copy

Copy is doing the most quietly-bad work in the current build. A few changes alone will move the trust needle.

01

Error copy is alarmist when the data state is normal.

"Pin location not registered in database" in red, listed under every polling centre that hasn't been pinned yet, makes 80% of stations look broken. Replace with calm: "Needs a pin · ochre" + a clear CTA.

02

"Click to Finish" appears on a touch device.

Should be "Tap to confirm" or, better, an explicit verb: "Save this pin." Avoid mouse verbs on mobile.

03

"FORM 3X" is in caps on the wordmark but body copy says "Kura Zetu."

Pick one casing and one name. "Kura Zetu" is the brand. The icon should be a glyph, not the words "FORM 3X."

04

"Welcome Back" is the most generic SaaS string on Earth.

Replace with what the user actually came to do. "Your phone, your verified Form 34A." Or just the brand title.

05

"Verify Polling Centers" then "Update Center Info" then "Map Missing Centers" — three actions for one mental model.

Group these under "PinVerify" with a single entry point. Branching happens after the user understands the intent.

08Two PinVerify directions

The brief asked for two distinct directions for the pin-on-map step. Both are in redesign.html as fully-drawn flows.

Direction A · Snap-to-known + walk-to-confirm

Search by school/landmark name (not code). GPS pre-fills the candidate location. The "confirm" button only unlocks when the user is physically within 20 m of the consensus. Long-press 2 s to commit (haptic). The consensus cloud appears only on the receipt, so the user's pin isn't anchored by prior data.

Best for: first-time verifiers, election day, rural users on cheap phones.

Direction B · Consensus-first pin cloud

The user sees the cloud of all prior pins upfront, with the consensus centroid and a confidence number. They agree, disagree (drag + reason), or skip. Disagreements ≥ 50 m open a dispute that other verifiers can resolve.

Best for: power verifiers, off-election windows, web users with bigger screens.

My recommendation: ship A first. Add B in v2 as "Power mode" once you have a base of repeat users with track records to weight their disputes.

09What to ship first

Ordered by trust-and-usability return per engineering day. Week 1 is the embarrassment-prevention list. Month 1 is the foundation. Later is the v2 horizon.

Week 1 · stop the bleeding
  • Remove the string "Dummy" from every candidate display.
  • Catch the registrationErrorLogin debug leak before it renders.
  • Persistent "Not IEBC" band on every results page.
  • Replace the red Sign-In + yellow underline with the Ramani palette.
  • Replace the "Things are boiling nicely" splash with a textual loader + count.
  • Take the "Project Timeline" Kanban off the homepage.
  • Add station-name search alongside the polling-station code field.
Month 1 · foundation
  • Ship tokens.css + a mirrored RN token JSON. One change, both surfaces.
  • Adopt Public Sans + IBM Plex Mono. Drop Inter / Roboto.
  • Build PinVerify Direction A (search-by-name + walk-to-confirm).
  • Form 34A capture: glare / blur / brightness detection at capture, torch toggle, page count.
  • OCR review screen with confidence-tinted rows (low-confidence in ochre).
  • Web dashboard rebuild: stacked bar + hex map + leaderboard. No donut chart.
  • One icon set: Lucide on web and mobile. Decommission Font Awesome.
  • Phone-OTP-only auth, biometric local unlock optional on mobile.
Later · v2 horizon
  • Hex-grid country view as the primary results navigation.
  • Community Notes ranking + author privacy + anti-harassment surface.
  • PinVerify Direction B as opt-in "Power mode."
  • Offline-first sync with explicit queued-submission UX.
  • Mapbox / MapLibre offline tile bundles for rural Kenya.
  • System dark mode (already in Ramani — it's the default).
  • Screenshot-resilient chart watermarks on share.

10Stack — keep, swap, watch

The bones are right. A few targeted swaps for design ergonomics.

KEEP Django + React + Tailwind

Right shape for a backend-heavy civic tool with a small frontend team. Tailwind reads the CSS-var token system natively — keep it.

KEEP Expo / React Native 0.79

Right choice for an Android-first deployment. The expo-camera, expo-location, expo-haptics, expo-local-authentication stack already covers the Form 34A flow primitives.

SWAP react-native-paper ~2–3 days

Paper's Material 3 doesn't share tokens with Tailwind cleanly. Move to NativeWind so the same --kz-* CSS vars drive both web and mobile. (gluestack is the alternative if you want Stitches-style runtime variants.)

SWAP react-native-gifted-charts ~1–2 days

Causes the donut-label collisions on the current dashboard. Move to Victory Native XL (better tabular-figure support, no SVG label overlap). Stacked horizontal bar is the default — donut should be optional and never the only view.

CONSIDER react-native-maps + Google → MapLibre + offline tiles ~5–7 days

Big win for rural-Kenya offline use: pre-bundle the country's vector tiles in the APK (~20 MB). Removes the per-MB cost of map loads on election day. Higher risk migration so v2-bound.

KEEP expo-secure-store + expo-local-authentication

Right pair for the biometric local-unlock pattern in the redesign. No change.

KEEP @react-native-community/netinfo

Powers the offline / stale-data state we lean on heavily. Already correct.

ADD expo-image-manipulator ~0.5 day

Resize Form 34A captures to 1024 px wide / JPEG q=0.85 (~400 KB) before queueing. Keeps the data-cost estimate (KES 1.20) accurate but drops the actual bytes ~6×. Critical for 2G/Edge rural uploads. Captured pages stay readable for OCR; the original full-res photo is retained on-device for 14 days for reverification appeals.

WATCH lottie-react-native

Not the library's fault — but every place it's used in the current build is a bad use. If after this audit no Lottie file survives, the dependency can come out entirely.

11What I would not change

The brief asked me to defend the parts that already work. Resist anyone's instinct to redesign these on a whim.

01

Phone-number-first identity.

Right call for Kenya. Email-first would have been a disaster — most users don't have or check an email account they'd trust with civic-tech. Sticking with phone OTP, with biometric local unlock on repeat, is exactly right.

02

Form 34A as the source of truth.

The legal final paper form is the only piece of state that everyone — citizens, parties, IEBC, courts — accepts. Building the whole platform around photographing it at the polling station is the correct anchor. Don't ever shift to digital-only entry.

03

The "What it IS / IS NOT" table.

The single most honest piece of UI in the product. The current visual treatment is dated, but the structure — five aspects, two columns, calm tone — is exactly right. I've redesigned it in redesign.html → Web · Landing without removing a row.

04

The 5-level electoral geography.

National → County → Constituency → Ward → Polling Station mirrors Kenyan electoral law. Don't flatten it for "simplicity." The complexity is the country.

05

The PinVerify points system (+10 / +15 / +2).

Incentives are calibrated correctly — confirming is worth less than correcting, skipping (admitting uncertainty) is rewarded above zero. Keep the numbers. Lose the gradient.

06

"Powered by Kiongozi" lineage disclosure.

Tucked under the wordmark in three places — exactly the right amount of disclosure. Keep it. It's quietly honest about the parent organization without putting them on the headline.

12One paragraph to end on

Kura Zetu is doing the hardest thing in Kenyan civic-tech right now: standing next to the IEBC without standing against it. The product mission is sharp. The visual language has been catching up to a mission like that since 2017, when the IEBC's own results portal collapsed and Kenya learned what parallel tallies were for. Ship the week-one list before election day; ship the month-one foundation by the registration deadline. The rest can wait. The point is not perfection. The point is a tally citizens can show each other and trust.
